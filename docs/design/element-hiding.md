# 手动隐藏网页元素

记录浏览器窗口里「魔法棒」功能的产品决策、判定规则与踩坑点。代码位置：
`Sources/NeatWebApp/Features/Browser/BrowserElementHidingScript.swift`（注入页面的脚本）、
`BrowserSelectorFinderScript.swift`（内嵌的第三方选择器生成库）、
`BrowserSession.swift`（规则状态与持久化）、
`BrowserContainerView.swift`（顶栏按钮与还原面板）。

## 产品形态

顶部让位带右侧有一个魔法棒按钮，点开是一块小面板：

- 「挑选要隐藏的元素」：进入挑选模式，鼠标划过时高亮、页面其余部分压暗，**点一下就隐藏**。
- 下面是这个网页应用已经隐藏掉的元素清单，按「当前网站 / 其他网站」分组，每条可单独恢复，底部一个「全部恢复」。
- 隐藏成功后页面底部弹一条五秒的「已隐藏 ×× · 撤销」提示，兜住误选。

挑选模式下按 Esc 退出，再点一次魔法棒也是退出。

## 已裁定、不要推翻的决策

### 1. 挑选时不给任何调整层级的操作

同类产品（uBlock Origin、AdGuard Assistant）都提供「扩大／缩小选中范围」的按键，本应用**刻意不做**：
用户要的是「把这块烦人的东西弄掉」，不是理解网页的层级结构。高亮框圈住什么，点下去消失的就是什么。

代价见下一条——不做层级调整，就必须把「指针命中的元素」自己扩到视觉上完整的一块。

### 2. 隐藏的是「视觉上最小的完整一块」，不是字面意义上最小的元素

指针落在广告里的一张图上时，字面意义上最小的元素是那张图，隐藏它只会留下一个空框子。
所以从命中元素往外走，满足两个条件就继续往外：

- 父级面积不超过当前的 **1.5 倍**（父级只是多了内边距／边框，视觉上还是同一块）；
- 父级面积不超过**半个视口**（防止一路吞掉整页）。

这两个阈值是这个功能好不好用的关键，改之前先想清楚会不会退化成「要么只隐藏一张图，要么整页消失」。

### 3. 规则按站点生效，不按页面

用户隐藏掉侧栏广告后，翻到同一站点的下一页不该又冒出来。`www.example.com` 与 `example.com`
归一化成同一个站点，否则用户会觉得「刚隐藏过又回来了」。

### 4. 用注入样式压掉，不用系统原生的内容拦截规则

苹果给 WebKit 提供了原生的元素隐藏能力（`css-display-none`），性能更好，但它改一条规则要把整份规则
重新编译再重载，做不到隐藏瞬间生效与一键还原。本功能的产品形态就是所见即所得 + 随时恢复，
所以走注入样式。日后若要做「导入广告过滤规则订阅」这类批量场景，才值得把原生规则加回来做补充。

### 5. 选择器生成直接复用成熟库，不自研

把用户点中的元素反推成一条既唯一又稳的选择器，是这个功能里最容易做砸的一步。
内嵌 [antonmedv/finder](https://github.com/antonmedv/finder) v4.0.2（MIT，1.5KB），原样保留，
只去掉了 ES Module 的 `export` 并包成立即执行函数——注入页面后不能污染网页自己的全局变量。
升级时直接换上游文件重做同样两步改动，不要在里面加本项目的逻辑。

同类的完整实现（uBlock Origin 的选择器、AdGuard Assistant）是 GPL-3，只能借鉴交互设计，**不能复用代码**。

### 6. 藏完立刻数命中数，宽规则主动告警、不静默

选择器生成库保证的是「在当前页面唯一」，但规则是按站点生效的——页面内唯一不等于全站安全。
通用工具类（如 Tailwind 的 `.visible`）、位置选择器（如裸 `li:nth-of-type(2)`）在当前页可能只命中用户指的那一块，
在全站却能命中几十上百个节点：每条都拼成 `display: none !important` 注入后，页面每次增量更新、每次窗口缩放
都要重新匹配一遍，长对话、长列表站点会越用越卡，还可能把正常 UI（输入框、流式输出）直接藏掉。

所以隐藏成功后立刻在页面里数一遍该选择器的命中数，超过 `broadRuleMatchLimit`（30，见
`BrowserElementHidingScript`）就回传 `broad` 消息，面板的提示区告诉用户命中了多少处、去还原最近隐藏的那条。
只告警不拦截：误报时用户忽略即可，漏报才真的伤人。阈值改动前先掂量两边——调太低会打扰正常的单块隐藏
（如连着藏一组广告），调太高则全站炸弹进来了也不吱声。

证据：2026-09-22 ChatGPT 打字与缩放卡顿，主因就是 5 条这类规则（含全站 `.visible`），另见
[长页面把窗口卡死](../troubleshooting/2026-09-18-long-page-webview-jank.md) 的 Evidence。

## 实现约束

- **注入时机必须是文档开头**。晚一步用户就会先看见要隐藏的东西闪一下再消失。
- WebKit 只允许整批清空用户脚本、不能单独摘掉某一条，所以隐藏规则一变就得把整套脚本重装一遍。
  装配顺序集中在 `BrowserUserScripts.install`，新增注入脚本时加到那里，不要散在各处。
- 隐藏规则一变要做三件事，缺一不可：存盘、把已经打开的页面立刻改过来、把后续页面的注入脚本也换掉。
- 选择器里出现花括号说明它已经不是选择器了，必须在存盘和拼样式两处都拦掉，否则会把后面的规则整片带坏。
- 持久化字段 `hiddenElements` **必须是可选的**。老版本存下来的偏好里没有这个字段，写成非可选会让整份
  偏好解码失败，用户的缩放、置顶、窗口位置跟着一起丢。对应断言在
  `Tests/NeatWebAppRuntimeTests/BrowserElementHidingTests.swift`。
- 自己的界面元素（高亮框、提示条、样式表）统一打 `data-neat-webapp-ui` 标记，挑选时跳过，
  否则用户会选中高亮框本身。
- 页面内唯一的承诺只在挑选当时、当页成立，不要把它当成全站安全的依据；宽规则靠上面的回报告警兜底，
  不要在生成库里为「全站命中数」再做一次预判——生成库是第三方原样保留的代码，项目逻辑不进去（见决策 5）。

## 已知边界

- **只管主文档**。内嵌小窗口（iframe）里的元素首版不支持。
- **网站改版后规则可能失效**：要么隐藏不到东西，要么误伤别的内容。当前靠清单里逐条恢复兜底，
  没有做「匹配不到就提示」——这是首版明确留下的缺口。
- 不支持按文字内容匹配这类扩展语法（AdGuard 的 ExtendedCss 那套），首版不做。

## 验收

改这块之后必须验证：

1. 在一个真实站点上点隐藏，元素立即消失；刷新页面、翻到同站另一页，元素仍然是隐藏的。
2. 从面板里恢复，元素立即回来。
3. 关掉窗口重开，隐藏状态还在。
4. 挑选模式下点击不会触发网页自己的跳转或点击。

注入脚本的逻辑改动可以先在模拟 DOM 里跑一遍再上真机：把两个 Swift 原始字符串里的 JS 抽出来，
用 jsdom 造一棵带手工盒子尺寸的 DOM（jsdom 没有排版引擎，必须自己替 `getBoundingClientRect` 兜底），
就能验证「往外扩到视觉完整一块」的判定、站点归一化和样式生成。这一步只验 JS，Swift 侧仍需真机构建。
