# 新打开网页应用：启动盖

记录「点开一个尚未运行的网页应用」时，如何盖住独立进程启动空白。运行机制见 [architecture.md](../architecture.md) 的 Launch Flow，本文不重复步骤。

## 当前规则

用户点开一个**还没在跑**的网页应用时，宿主立刻在真窗将要出现的位置盖上一扇同框白窗。这只是盖子，不是第二套界面。

- **同一框**：位置和尺寸必须与真窗完全一致。宿主只算一次，既用来盖住，也原样写进启动参数；运行时禁止再算一遍，也禁止刚出现时再挪位置。
- **铺满可用桌面不算用户窗口**：系统缩放、贴边或第一次上屏可能把框变成整块可用桌面。这种框不能写进窗口记忆，也不能拿来盖住；应回退到用户上次真正拖过的小窗，没有则用默认大小。侧边 Dock 正在显示时，「可用桌面」还要再扣掉 Dock 所在边的整条厚度，盖子和真窗都按这块算，不能铺到刘海底下。
- **真窗必须锁住这一框**：挂上网页内容后，系统会按页面理想尺寸改窗（常见是先铺满再缩成一条）。第一次揭盖前，运行时必须禁止系统窗口记忆、禁止页面内容反推窗口大小，并在上屏后再套回宿主给的那一框。
- **同一外壳**：盖子用和真窗一样的窗口样式，内容是空白白底。不要另做顶栏、图标、应用名或骨架屏。
- **没有交接动画**：揭盖是立刻拿走，不要淡出、交叉淡入或缩放。系统默认的窗口弹出缩放必须关掉。
- **等第一帧再揭**：真窗先出现在盖子下面，但**不要**在网页画出第一帧之前告诉宿主「已经可见」。还没画完就揭，会闪一下空窗。盖子可以短暂多留一会儿；宁可白一下，也不要闪空窗。
- **不要提前抢键盘焦点**：第一次把真窗拉到前面时不要立刻变成键窗。变成键窗会发出「窗口已聚焦」，宿主若据此揭盖，会在第一帧之前就把盖子拿掉。
- **盖子必须比真窗高一层**：同层盖住会被当成「挡住了」而把真窗立刻收进侧边栏。
- **宿主是菜单栏常驻**：不把应用带到前面的话，盖子会画在别的应用下面，看起来像没点中。
- **盖子不要自己的阴影**：真窗的阴影才是唯一的那一层，否则会叠出双影。
- **只走用户新打开**：已经在运行的唤出、从侧边 Dock 展开、后台健康重启都不盖。健康重启也不锁死成「宿主算好的那一框」。
- **窗口位置两边读同一份**：宿主和运行时是两个进程，不能各写各的偏好。上次拖过的大小必须两边都看得见。
- **量默认尺寸用内容尺寸本身**：本窗内容铺满外框，不要用系统外框换算，更不要为了量尺寸临时建一扇窗再关掉。

已经在运行的窗口不走这层盖。启动失败、崩溃、收起或隐藏时立刻揭盖，不要让白窗卡住。盖子最多等一小会儿第一帧；超时也必须揭，不能永远盖着。

## 验收

打开一个**尚未运行**的网页应用：

1. 点击当下，同位置同尺寸立刻出现一扇白窗，不要空等、不要跳、不要先铺满屏幕再变成小窗。
2. 白窗可以短暂停留；揭开时看到的应是已经画出的页面，不是空窗闪一下。
3. 不要出现第二套顶栏、居中图标、应用名，也不要淡入淡出。
4. 真窗出现后不要被立刻收进侧边栏。

仍在闪的话，先查是不是第一帧之前就揭了，或两个进程之间露出了空隙，或真窗在挂上网页后被系统改了框。**不要**因此加回淡出或第二套界面。

## 被否决的方案

### 让真窗跟页面理想尺寸走

看起来像「网页自己知道该多大」。实际是系统在第一次上屏时改框，盖子还停在宿主算的尺寸上，用户看见全屏白屏再缩成小窗。

结论：第一次揭盖前锁死宿主给的框。不要为了对齐去让盖子跟着页面理想尺寸变。铺满可用桌面的框不能写进窗口记忆。

### 宿主和运行时各自算窗口位置

两边读的是两份互不相通的偏好。用户上次拖过的大小宿主看不见，盖子和真窗对不齐。

结论：位置偏好必须是同一份；宿主算好的那一框还要写进启动参数，运行时原样套上。

### 临时建一扇真窗来量外壳厚度

为了算出「内容区对应多大的外框」去创建再关掉一扇系统窗口，会在稍后释放对象时闪退。

结论：用系统提供的外框换算，不要为了量尺寸去创建窗口。

### 用浮动面板当盖子

面板和普通窗口的边框厚度不一样。即使外框数字相同，肉眼仍能看出换了一扇窗。

结论：盖子必须是和真窗同一类窗口、同一套样式。

### 居中图标 + 应用名的启动闪屏

看起来像另一个应用在启动，和真窗对不上。用户明确否决「拆成第二套界面」。

结论：盖子只是白底，不要品牌闪屏。

### 仿造真窗顶栏的骨架屏

同样是第二套界面。交接时用户会感觉从假窗切到真窗。

结论：不要在盖子上画任何控件或顶栏。

### 淡出 / 交叉淡入揭盖

淡出把系统弹出缩放和尚未画完的空窗露出来，闪得更明显。用户要的是连续，不是过渡特效。

结论：揭盖立刻拿走。闪的根因是揭早了或系统缩放，不是缺动画。

### 真窗一出现或一聚焦就揭盖

窗口被拉到前面、变成键窗时就会报「可见 / 已聚焦」。此时网页往往还没画出第一帧，揭开就是空窗闪一下。短暂让出时间片再揭，同样太早。

结论：等网页第一帧画完再报可见；盖着的首次出现期间，聚焦通知不得揭盖。
