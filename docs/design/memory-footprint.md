# 内存占用：体验优先约束

文档定位：宿主 / 运行时内存占用的**本产品**约束与验收数字。

## 权威

跨产品模式（压力只丢可重建物、禁止卸 `WKWebView`、MemoryPressure 闭包禁止 `@MainActor`）：

→ [macOS 原生应用内存优化指南 §5.8 / §6](~/.config/agentsync/docs/MACOS_APP_MEMORY_OPTIMIZATION_GUIDE.md)

## 已裁定产品约束

1. **不牺牲体验**：收进侧边栏仍秒开；网页会话不丢；每个网页应用独立进程；不得把「省内存」做成用户可感知的变慢或重载。
2. **压缩策略**：采纳「用 CPU 换内存」，但**优先借系统内存压缩机**（不活跃匿名页由内核 WKdm/LZ4 压解）。禁止自研「把整页网页引擎堆压进自定义缓冲再解压」——那等价于卸页再装回。
3. **压力响应只丢可重建物**：系统 memory pressure 时，可丢掉可从磁盘重建的宿主缓存（如网站图标内存缓存）、停图标预取；**禁止**因压力卸掉 `WKWebView` 内容，**禁止**因压力直接结束仍保活的运行时进程。

## 架构事实（与占用强相关）

- 宿主常驻菜单栏；每个网页应用一个 `NeatWebAppRuntime` + WebKit 内容进程族。
- 收进侧边栏是窗口生命周期动作，**故意保留进程**以便秒开与状态恢复（见 [window-auto-collapse.md](window-auto-collapse.md)、[architecture.md](../architecture.md)）。
- 网页引擎内容进程是多开场景下的占用大头；在体验优先前提下，这是设计成本，不是实现疏忽。
- **长页面卡死不是缺 GPU、也不能靠卸页来修**：对话、信息流一类站点会把大量历史块留在页面上，WebKit 主线程被排版拖死；同一症状在 Safari 上也会出现。排查见 [长页面把窗口卡死](../troubleshooting/2026-09-18-long-page-webview-jank.md)。

## 允许做的优化

- 网站图标按显示像素下采样后再解码 / 落盘；内存侧有界、可丢弃（磁盘权威）。
- 过渡用整窗位图不得长期挂属性；动画结束立即释放。运行时已删除从未赋值的整窗截图捕获路径，避免以后误加回全窗位图常驻。
- 订阅 `DispatchSourceMemoryPressure`，按上列约束收缩可重建宿主缓存。
- **压力回调隔离（硬约束）**：事件闭包跑在后台队列，禁止继承 `@MainActor`；须 `@Sendable`，清缓存再 hop 回主线程。写错会在系统一报压力时把宿主直接闪退（见 [宿主内存压力回调闪退](../troubleshooting/2026-09-05-host-memory-pressure-mainactor-crash.md)）。
- 修真正泄漏与无界增长。
- 观测 footprint / dirty / compressed；健康监控阈值仍是异常兜底，不得改成「日常杀胖进程」省内存。

## 明确禁区

- 收起后结束运行时 / 卸网页再打开重载。
- 多网页应用共用内容进程换内存（破坏隔离）。
- 应用内自研整页堆压缩解压。
- 依赖私有 API 或手动调 kernel compressor。
- 把「活动监视器里 Compressed 上升」当成必须消掉的故障——压力下系统压缩不活跃页是预期行为。

## 验收口径

- 侧边栏点开仍秒开，页面滚动位置与登录态仍在。
- 压力场景下图标可短暂从内存消失再读盘，界面不闪崩、不强制重载网页。
- 主 KPI 是 physical footprint（及 dirty / compressed），不是 free RAM 或单独 RSS。

## 基线摘录（2026-09-05，本机，v0.3.11 / 3029）

固定观测：两枚已收进侧边栏的运行时 + 菜单栏宿主。主 KPI 为 `footprint` / `vmmap` physical footprint。

| 进程 | Footprint | 备注 |
|---|---|---|
| 宿主 `NeatWebApp` | ~91 MB（峰值 ~124 MB） | 含 CG Image / CoreAnimation / Malloc Large；RSS 会被压缩器压低，勿当主指标 |
| 运行时 A / B（已收起） | 各 ~48–49 MB | 运行时进程内 WebKit Malloc 仅数 MB；网页内容进程另计 |

归因结论：多开保活场景下，每个运行时壳约几十 MB 是「秒开」的设计成本；宿主侧可优化的是图标解码浪费、可丢弃缓存与压力配合。完整四场景（零应用 / 开 1 / 收起 N / 重复开合）在发版后同机复测写入本节或排障记录。

**2026-09-05 优化后复测（Debug 覆盖安装）**：新鲜宿主约 61–68 MB footprint；连续 5 次唤起主窗口 footprint 稳定在 ~67–68 MB，未见单调上涨。旧会话宿主曾到 ~91 MB（含更多已驻留图像区域），与「可丢弃缓存 + 下采样」方向一致。
