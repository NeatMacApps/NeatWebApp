# 侧边 Dock 在多显示器之间乱跳

## 现象

接了两块显示器时，侧边刘海 Dock 会自己从一块屏跳到另一块屏。触发点看起来毫无规律——实际上是在另一块屏上点了一下窗口之后，Dock 下次刷新就整块过去了。

## 根因

`NSScreen.main` **不是"主显示器"，而是当前键盘焦点所在的那块屏**。侧边 Dock 在还没记住过屏幕时用它兜底选屏，于是用户每次把焦点切到另一块屏，Dock 重新计算位置就跟着跑。

放大这个问题的还有第二处：宿主每次刷新 Dock（有 WebApp 收起 / 展开、图标更新等）都会把偏好里的屏幕 ID 原样传下来，偏好里没记录时传的是空值，会把本次会话已经解析出来的屏幕冲掉，于是每次刷新都重新走一遍兜底逻辑。

## 修复

- 选屏兜底顺序改为：偏好记录的屏幕 → Dock 当前所在的屏幕 → 屏幕列表第一块（菜单栏所在的真正主显示器）。**任何位置都不再使用 `NSScreen.main`**，拖动过程中的兜底也一并换掉。
- 兜底解析出的屏幕会就地记住；刷新时若偏好里没有屏幕记录，保留已记住的那块，不再被空值冲掉。

## 验证手法

把焦点挪到另一块屏，确认 `NSScreen.main` 的 ID 确实变了，而 Dock 面板的屏幕坐标一动不动。可以用一个临时的 AppKit 小程序在副屏开一个窗口并激活自己，再用 `CGWindowListCopyWindowInfo` 读宿主那个窄面板（宽度约 47 点）的位置，前后对比。

注意：Dock 只显示**宿主应用目录里已配置**的 WebApp。临时造一个不在目录里的应用去触发收起，Dock 不会出现，会误判成"修复没生效"。

## 相关

同批还去掉了 Dock 图标上那圈自绘的键盘焦点描边——它只在按钮取得焦点时出现，表现为"图标偶尔莫名多一圈边框"。侧边 Dock 是非激活面板，本来就走不到键盘导航，去掉不影响无障碍。
